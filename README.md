# Сервис модерации объявлений

## Запуск

Выполните команды из корня проекта в активированном виртуальном окружении Python.

```bash
pip install -r requirements.txt
docker compose up -d --wait
pgmigrate -d db -t latest migrate
fastapi dev
```

Если `psycopg2` собирается из исходников как зависимость `yandex-pgmigrate`, понадобятся C-компилятор, заголовки Python и `pg_config`. В Debian и Ubuntu их предоставляют пакеты `build-essential`, `python3-dev` и `libpq-dev`.

По умолчанию сервис подключается к базе `hw` на `localhost:5435`. Адрес подключения можно задать переменной `DATABASE_URL`. Параметры подключения для миграции хранятся в `db/migrations.yml`.

[Документация API](http://127.0.0.1:8000/docs)

## Предсказание

`POST /predict` принимает параметры объявления в JSON. `POST /simple_predict` принимает положительный целочисленный `item_id` как query-параметр и загружает данные объявления и продавца из PostgreSQL одним запросом.

```bash
curl -X POST 'http://127.0.0.1:8000/simple_predict?item_id=1'
```

- `200` — JSON-значение `true`, если нарушений нет, или `false`, если есть.
- `400` — невалидные входные данные.
- `404` — объявление с таким идентификатором отсутствует.
- `500` — ошибка при получении данных или выполнении предсказания.

Подтверждённый продавец проходит модерацию всегда. Для неподтверждённого продавца требуется хотя бы одно изображение.

## Тесты

Запустите PostgreSQL и примените миграцию, затем выполните `pytest`. Интеграционные тесты используют ту же локальную БД по умолчанию. Для другой тестовой БД с применённой миграцией задайте `TEST_DATABASE_URL`. Фикстуры создают записи с автоматически назначенными идентификаторами и удаляют их после каждого теста.
